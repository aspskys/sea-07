# SeaInfra LLM 验收

读取统一契约、`config.json`、`state.json`、权威来源和实际改动。只验收当前环境，不继承另一环境结论。

## 检查

1. **静态**：确认 `protocol` 是内置允许值，`protocol_probe` 指向同环境、同 Base URL、同模型且结果为 `supported` 的报告；调用只在设计的信任边界发生；配置实际可加载；输入输出被校验；错误、取消、限流和重试有界；流式资源能关闭。运行项目测试、类型检查或构建。
2. **连通性**：先重跑内置协议探测脚本，确认所选协议仍为 `supported`，再使用当前环境凭证按所选协议发起最小、低成本真实请求。核对鉴权、模型标识、响应结构、请求 ID/用量等来源规定的字段；不能把 DNS/TCP、端点存在或标准错误响应当作模型可用。
3. **业务闭环**：从真实入口触发本期用例，确认业务输入进入适配层、结果到达调用方并正确持久化/展示；再覆盖至少一个可控失败或超时路径。若声明流式能力，验证首包、完整结束和主动取消。

## 结论

- 任一必需层失败：执行 `block llm --reason <具体原因>`，列出复现命令和下一步，不生成通过证据。
- 全部通过：按统一契约写 `.agents/seainfra/evidence/llm-<environment>-<timestamp>.json`。证据引用权威来源、命令、代码位置和脱敏请求标识，不记录完整密钥或敏感内容。
- 证据写入后执行 `complete llm --env <环境> --evidence <文件>`。脚本拒绝格式不完整或环境不匹配的证据。

生产真实请求必须先获得用户确认；未获确认时连通性或闭环只能标 `not_applicable`，且写明原因，不能伪装为已实测。
