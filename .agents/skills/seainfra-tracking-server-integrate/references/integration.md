# 跨语言服务端接入

## 1. 建立服务边界

从进程和部署单元出发，而不是从文件扩展名出发：

1. 找到接收请求、消费消息或执行定时任务的入口。
2. 找到配置加载、依赖注入、启动和优雅退出位置。
3. 找到持久化磁盘或日志卷的部署配置。
4. 识别短生命周期命令、Serverless、常驻服务和批处理；它们的 flush 策略不同。
5. 多服务仓库逐个确认目标服务，不把一个服务的配置或身份语义套给其他服务。

## 2. 选择传输方式

按以下顺序决策：

1. 已有经过验证的 StarUnion 适配层：复用并补测试。
2. 目标语言存在官方、版本明确且与当前环境兼容的 SDK：使用官方 SDK。
3. 没有官方 SDK、版本/API 无法确认或用户明确要求无 SDK：读取 `http-transport.md`，实现跨语言 HTTP 适配层。

不要依据其他语言示例猜测当前 SDK 的构造函数、flush、close、队列或重试 API。安装任何包前确认包名、来源、版本与仓库包源。

## 3. 设计最小适配层

适配层至少隔离以下职责，具体接口风格遵循项目现有约定：

```text
initialize(config, lifecycle)
track_event(identity, event_name, event_time_ms, properties)
set_user_properties(identity, event_time_ms, operations)
flush_or_close(deadline)
```

业务代码只提供业务事实和字段，不负责加密、签名、批量、重试、备份或 host 选择。适配层应允许注入替身，以便测试事件名、触发次数、身份映射和属性类型。

## 4. 配置与安全

- 配置和密钥只从星云项目管理下载，并通过部署密钥系统或运行环境注入。
- release 与 production 使用各自配置，不跨环境复用；host、项目和密钥必须属于同一环境。
- 仓库只保留无敏感值的配置键说明。不要提交下载的配置文件、真实 `aes_id`、`aes_key`、`aes_secret` 或完整示例。
- 日志只记录 request ID、事件名、条数、失败 uid、错误类别和必要摘要；不记录密钥、签名、密文对应明文或敏感属性。

## 5. 身份与事件边界

- 为 account、distinct、role ID 建立明确映射表，说明来源、稳定性、匿名到登录态的关系和缺失策略。
- 成功事件应位于不可逆业务结果或事务提交之后。失败事件应位于错误已确定且不会继续成功的分支。
- 消息消费场景要明确“生产成功、消费成功、业务处理成功”中的哪一个事实属于事件语义。
- 重试、重复投递和事务回滚可能导致重复事件；使用稳定业务键或传输 `uid` 保持幂等语义。

## 6. 可靠性与生命周期

- 官方 SDK：确认初始化失败行为、队列容量、队列满策略、批量大小、超时、重试次数、持久化备份、重放和 flush/close API。
- HTTP：实现有限重试、退避和抖动；仅对可重试错误及部分失败条目重试，使用同一稳定 `uid`。
- 备份目录必须位于持久化存储，并确认权限、容量、轮转、保留期、告警和重放责任人。
- 优雅退出需停止接收新任务、等待或截止 flush、保存未发送数据，再退出。短生命周期任务必须显式等待上报结果或持久化交接。
- 埋点故障不能阻塞或回滚核心业务，但必须暴露指标、结构化日志或告警。

## 7. 测试矩阵

- 单元测试：事件名、属性类型、必填字段、身份映射、时间单位、恰好一次调用。
- 边界测试：身份缺失、属性缺失、超大批次、队列满、超时、退出中上报。
- 失败测试：网络错误、认证错误、服务端错误、部分批量失败、重试耗尽、备份和重放。
- 集成测试：在非生产环境触发真实业务路径，核对 request ID/uid 与 Starry 统计。

测试夹具只使用假密钥和脱敏数据。加密实现需要官方测试向量或与已验证实现互操作；没有证据时不得仅凭“请求返回”宣称算法正确。
