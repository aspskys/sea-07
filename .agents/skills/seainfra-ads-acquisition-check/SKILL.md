# SeaInfra 广告买量验收

按 `platforms` 和 `conversion_events` 逐项验收。测试设备或测试链接的结果不能自动代表其他端或媒体渠道。

## 检查

1. **静态**：应用/包标识和环境匹配；SDK/脚本在正确生命周期初始化；隐私同意逻辑符合来源；归因参数持久化有界；普通/延迟深链路由一致；事件名、字段、收入币种和去重键与映射表一致。运行测试和构建。
2. **连通性**：按平台官方测试方法使用测试设备/链接验证 SDK 初始化、归因回调和深链。服务端回传核对接受结果与稳定去重键；网络成功不等于归因成功。
3. **业务闭环**：完成一次可识别的测试安装/访问到目标落地页，再触发每个本期关键转化。等待平台规定处理窗口后，使用平台调试视图或 `$ads-data-query` 在 `af_agent_data` 视图核对安装、事件、渠道/活动和收入字段。

查询 AppsFlyer 数据时必须遵循 `$ads-data-query`：先列视图、describe、同过滤条件 count、少量 sample，再做窄范围查询；使用日期过滤且不查询原始 `_parquet` 表。

证据记录平台、测试设备/链接标识、归因结果、每个事件的脱敏唯一键、数据时间窗和最终查询摘要。平台处理窗口未结束或数据未出现时保持 `blocked`，不得把客户端日志当作最终归因。

所有平台与事件通过后写 `ads_acquisition-<environment>-<timestamp>.json`，执行 `complete ads_acquisition`。真实投放或预算操作仍需单独授权。
