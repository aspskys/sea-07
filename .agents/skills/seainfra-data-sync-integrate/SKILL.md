# SeaInfra 数据同步接入

先读 `.agents/skills/seainfra-onboarding/references/contract.md`、统一配置和状态，只处理 `data_sync` 模块。测试与生产环境分别收集、分别交付、分别验收。

## Harness 约束

1. 确认 `data_sync` 已被用户选择；从项目证据识别已有数据库和表，但凭证、网络方式和同步范围必须由用户或权威配置确认。
2. 把确认值写入 `.agents/seainfra/config.json` 当前环境的 `data_sync`，再运行 `validate data_sync --env <环境>`。
3. 配置完整后执行 `begin data_sync --env <环境>`，再生成交付文档；禁止用示例值填满配置。
4. 文档交付和映射创建只代表接入工作已准备好，不代表数据已同步，也不得写 `completed`。

## 技能目标

当业务方需要将数据库中的数据同步到数仓时，使用本技能完成以下工作：

1. 确认业务方使用的数据库类型。
2. 根据数据库类型收集对应的同步配置。
3. 告知业务方数据库必须能够通过公网或内网访问。
4. 生成一份标准的数据库同步配置文档。
5. 明确告知业务方，需要将数据库同步配置文档反馈给“星云中台”支持人员。
6. 在当前项目的 `bigdata_config` 目录下创建业务数据表与数仓数据表的映射关系文档。
7. 将映射关系文档保留在当前项目本地，作为实现数据同步任务的依据。

## 触发条件

当用户提出以下类型的需求时，使用本技能：

- 同步数据库数据
- 同步数据表
- 将业务数据同步到数仓
- 从业务数据库导入数据
- 配置数据库同步
- 新增数据同步任务

## 支持的数据库类型

根据业务方的实际情况，支持以下数据库类型：

- Firebase
- MySQL
- PostgreSQL
- MongoDB

每次只收集当前业务实际使用的数据库配置。

## 执行流程

### 步骤一：确认数据库类型

根据业务方的实际业务确认数据库类型。

数据库类型只能是：

- Firebase
- MySQL
- PostgreSQL
- MongoDB

如果业务方已经明确数据库类型，不要重复询问。

### 步骤二：收集对应配置

根据数据库类型，仅收集该数据库对应的配置内容。

不要向业务方索取当前数据库类型不需要的配置。

如果业务方已经提供了部分信息，只询问缺失的信息，不要要求业务方重复提供。

### 步骤三：检查配置完整性

生成文档前，需要检查对应数据库的必填配置是否完整。

如果缺少必要配置，明确列出缺失项，并让业务方补充。

配置完整后，将确认值同步到统一配置并运行 `validate data_sync`。数据库类型统一写为 `firebase`、`mysql`、`postgresql` 或 `mongodb`；同步对象统一写入 `objects`；数仓引擎固定为 `redshift`，目标前缀固定为 `sync_`。

密码必须作为配置项提供。如果不适合在当前沟通渠道中直接提供密码，可以填写：

```text
通过安全渠道另行提供
```

### 步骤四：告知网络访问要求

必须明确告知业务方：

> 数据库必须能够通过公网或内网访问，否则无法执行数据同步。

公网访问时，业务方需要：

- 提供数据库公网访问地址。
- 开放对应的数据库端口。
- 将数据同步服务器的出口 IP 加入访问白名单。

内网访问时，业务方需要：

- 确保数据同步服务可以访问业务数据库所在内网。
- 提供必要的内网访问方式。
- 根据实际情况提供 VPN、专线或其他网络连接方案。

### 步骤五：生成数据库同步配置文档

 配置收集完成后，生成一份 Markdown 格式的数据库同步配置文档。

文档固定保存到：

```text
bigdata_config/data-sync-config.md
```

文档格式如下：

```markdown
# 数据库同步配置文档

## 基本信息

| 配置项 | 值 |
|---|---|
| 数据库类型 | {database_type} |
| 环境 | {environment} |
| 数据库 | {database} |
| GCP 项目 | {gcp_project，仅 Firebase 使用} |
| 需要同步的数据集合 | {collections，仅 Firebase 使用} |
| 表名 | {table_names，MySQL、PostgreSQL、MongoDB 使用} |
| 账号 | {username，MySQL、PostgreSQL、MongoDB 使用} |
| 密码 | {password，MySQL、PostgreSQL、MongoDB 使用} |
| 链接 | {connection_url，MySQL、PostgreSQL、MongoDB 使用} |
| 是否只读 | {read_only，MySQL、PostgreSQL、MongoDB 使用} |

## 网络访问要求

数据库必须能够通过公网或内网访问。

### 公网访问

- 数据库需要提供公网访问地址。
- 数据库端口需要允许同步服务器访问。
- 同步服务器的出口 IP 需要加入数据库访问白名单。

### 内网访问

- 数据同步服务需要能够访问数据库所在内网。
- 业务方需要提供可用的内网访问方式。
- 如有需要，请提供 VPN、专线或其他网络连接信息。
```

生成文档时，只保留当前数据库类型对应的配置项。

例如，Firebase 配置文档中不应出现账号、密码、链接和是否只读。

### 步骤六：交付数据库同步配置文档

数据库同步配置文档生成后，必须明确告知业务方：

> 请将生成的数据库同步配置文档反馈给“星云中台”支持人员，由“星云中台”支持人员根据该文档处理数据库接入和数据同步支持。

数据库同步配置文档的生成并不代表流程已经结束。

本技能生成该文档的主要目的，是让业务方将完整的数据库同步配置信息交付给“星云中台”支持人员。

如果当前 Agent 无法直接将文档发送给“星云中台”支持人员，需要明确提醒用户完成该交付操作。

### 步骤七：创建数据表映射关系文档

数据库同步配置文档生成后，需要在当前项目中创建业务数据表与数仓数据表的映射关系文档。

#### 目录要求

映射关系文档必须放在：

```text
bigdata_config/
```

如果当前项目中不存在该目录，需要先创建：

```bash
mkdir -p bigdata_config
```

#### 文件路径

映射关系文档保存为：

```text
bigdata_config/table-mapping.md
```

#### 数仓表命名规则

数仓表名称固定使用以下格式：

```text
sync_{业务表名}
```

示例：

| 业务数据表      | 数仓数据表           |
| --------------- | -------------------- |
| users           | sync_users           |
| orders          | sync_orders          |
| payment_records | sync_payment_records |

Firebase 和 MongoDB 的数据集合，也按照相同规则生成数仓表名称。

例如：

| 业务数据集合  | 数仓数据表         |
| ------------- | ------------------ |
| users         | sync_users         |
| conversations | sync_conversations |

#### 映射关系文档格式

```markdown
# 业务数据库与数仓数据表映射关系

## 数据库信息

| 配置项 | 值 |
|---|---|
| 数据库类型 | {database_type} |
| 环境 | {environment} |
| 数据库 | {database} |

## 数据表映射

| 业务数据表或集合 | 数仓数据表 |
|---|---|
| {business_table_name} | sync_{business_table_name} |
```

需要根据本次同步的数据表或数据集合，生成完整的映射关系。

### 步骤八：使用映射关系文档实现同步任务

`bigdata_config/table-mapping.md` 只保留在当前项目本地，不需要交付给“星云中台”支持人员。

该文件用于记录当前项目中的：

- 业务数据表或数据集合。
- 对应的数仓数据表。
- 业务表与数仓表之间的映射关系。

后续开发或执行数据同步任务时，需要以该文件中的映射关系为依据，实现对应的数据同步逻辑。

不要将数据库同步配置文档和 `table-mapping.md` 混为同一个交付物：

| 文档               | 用途                                     | 存放或交付位置                         |
| ------------------ | ---------------------------------------- | -------------------------------------- |
| 数据库同步配置文档 | 提供数据库接入和同步所需配置             | 反馈给“星云中台”支持人员               |
| `table-mapping.md` | 记录业务表与数仓表映射，指导同步任务实现 | 保留在当前项目的 `bigdata_config` 目录 |

## 接入阶段完成条件

只有完成以下事项后，才能进入统一 Check：

1. 已收集当前数据库类型所需的全部配置。
2. 已明确数据库必须能够通过公网或内网访问。
3. 已生成数据库同步配置文档。
4. 已明确提醒用户将数据库同步配置文档反馈给“星云中台”支持人员。
5. 已在当前项目中创建：

```text
bigdata_config/table-mapping.md
```

1. 已明确说明 `table-mapping.md` 保留在当前项目本地。
2. 已明确说明后续需要基于 `table-mapping.md` 实现数据同步任务。
3. 已执行 `check-start data_sync --env <环境>` 并转交 `$seainfra-data-sync-check`。

不得因为配置文档和映射文档存在就宣称数据同步完成。最终完成必须由 Check Skill 证明源库可达、目标数仓表存在且最小数据闭环通过。

## 最终输出

完成后，Agent 必须向用户说明：

1. 数据库同步配置文档已经生成。
2. 请将数据库同步配置文档反馈给“星云中台”支持人员。
3. 数据库需要确保能够通过公网或内网访问。
4. 本地已经生成业务表与数仓表映射关系文档：

```text
bigdata_config/table-mapping.md
```

1. `table-mapping.md` 保留在当前项目本地，不需要发送给“星云中台”支持人员。
2. 后续需要基于该映射关系文档实现数据同步任务。

最终提示示例：

```text
数据库同步配置文档已生成。

请将该配置文档反馈给“星云中台”支持人员，由支持人员根据文档中的数据库配置处理接入和同步支持。

请确保业务数据库能够通过公网或内网访问。

当前项目中已生成业务表与数仓表映射关系文档：

bigdata_config/table-mapping.md

该映射文档保留在当前项目本地，不需要发送给“星云中台”支持人员。后续请基于该文档实现具体的数据同步任务。
```

输出上述交付信息后，明确标注“接入阶段完成，等待数据同步验收”，执行 `check-start data_sync`，转交 `$seainfra-data-sync-check`。本 Skill 不得自行标记完成。
