# 发行端收银台对接文档（Skill）

> 本文档同时作为 **CLI / Agent Skill** 与人工对接手册。

## 1. 目标与范围

帮助发行方完成收银台接入全流程：

1. 确认渠道与业务形态
2. 商务申请三方商户
3. 向平台（九姜）申请应用，获取 `client_id` / 密钥并开通渠道(金鱼、柠檬水)
4. 按端完成研发对接
5. 研发完成后交测试，在**测试环境**验收，并同步**计划上线日期**
6. 测试通过后切换正式环境并上线

**不在本文展开**：具体请求字段、签名算法——一律以官方帮助中心与仓库 API 文档为准；错误码与常见问题见下方「参考文档」。

---

## 2. 总流程

```
① 确认渠道与业务 → ② 商务申请三方商户 → ③ 平台申请应用与开通渠道
→ ④ 研发对接 → ⑤ 交测试环境验收（并说明上线日期） → ⑥ 正式切换与上线
```

**进度 Checklist（CLI 可复制跟踪）**

```
- [ ] Step1 渠道与业务确认
- [ ] Step2 三方商户申请（商务）
- [ ] Step3 平台应用申请（client_id / 密钥 / 渠道开通）
- [ ] Step4 研发对接（服务端 / Web / Android / iOS）
- [ ] Step5 交测试：测试环境验收 + 明确上线日期
- [ ] Step6 正式环境切换与上线
```

## 3. Step1：确认接入渠道

### 3.1 收集信息

| 项 | 选项 |
|----|------|
| 业务类型 | 一次性购买 / 订阅 / 签约代扣 |
| 运行端 | Web / Android 内嵌 H5 / iOS 内嵌 H5 / Google Play / App Store |
| 目标市场 | 海外 / 国内 |
| 计划渠道 | 见下表 |

### 3.2 目前支持的渠道

| ID | 渠道 | 说明 |
|----|------|------|
| 1 | Adyen | 支持订阅 |
| 2 | PayPal | — |
| 3 | V5Pay | 支持订阅；**支持俄罗斯** |
| 4 | PayerMax | 支持订阅 |
| 5 | SEAPAY | 需接入大账号和钱包 |
| 6 | AIRWALLEX | — |
| 7 | ALLINPAY | 国内 |
| 8 | GOOGLEPLAY | App |
| 9 | APPSTORE | App |
| 10 | Checus | **支持俄罗斯** |

**选型要点**

- 国内优先评估 `ALLINPAY(7)`
- 海外 Web/H5：在 1～6、10 中按市场与商务能力选择
- **俄罗斯市场**：优先 `V5Pay(3)` / `Checus(10)`
- App 内购/订阅必须规划 `GOOGLEPLAY(8)` / `APPSTORE(9)`
- 收银台订阅优先：`Adyen` / `V5Pay` / `PayerMax`

## 4. Step2：商务申请三方商户

1. 按渠道清单找商务申请对应三方商户（MID/密钥等）。
2. 订阅类渠道申请时注明需开通订阅/自动扣款能力。
3. Google Play / App Store：配置商店商品与订阅项（非传统 MID）。
4. **可先用平台提供的测试商户**在测试环境联调，正式商户后补。

---

## 5. Step3：向平台申请应用

**对接人：PM 九姜**

提交内容建议包括：应用信息、需开通渠道、是否订阅/签约。
**若为安卓应用，还必须提供包体签名信息**（与包名一并提交）。

平台返回：

- 应用 ID（`client_id`）
- 应用密钥 / 签名相关信息
- 测试环境配置（平台可先提供测试商户）

**申请模板**

```text
【收银台应用开通申请】
应用名称(包名)：
运行端：Web / Android 内嵌 H5 / iOS 内嵌 H5 / Google Play / App Store
业务类型：一次性购买 / 订阅 / 签约代扣
开通渠道：1-Adyen, …
是否先提供测试商户联调：是
预计联调开始时间和验收时间：
对接研发：
包体签名信息（Android 必填）：
备注：
```

创建订单 → 拉起支付 → 异步通知验签 → **幂等发货** →（按需）退款/关单/查单。

## 7. Step5：研发完成后交测试环境验收

研发对接完成后，**先交付测试同学在测试环境验收**，不得跳过直接上正式。

**测试对接人**：慕斯、劲风、林新

### 7.1 提测要求（研发必须一并提供）

| 项 | 说明 |
|----|------|
| 提测范围 | 已对接端、已开通渠道、业务类型（一次性/订阅等） |
| 测试环境信息 | 测试 `client_id`、地址/包体等 |
| 自测结论 | 创单、支付、回调发货等关键路径已自测通过 |
| **计划上线日期** | **必填**：明确目标上线日（或上线窗口），便于测试排期与正式配置 |
| 已知风险 / 未完成项 | 如正式商户未就绪、某渠道延后等 |

**提测通知模板**

```text
【收银台对接提测】
应用/包体：
对接范围：端（Web/Android/iOS）+ 渠道（1-Adyen…）+ 业务（一次性/订阅…）
测试环境：已就绪 / 说明：
研发自测：通过（附关键单号样例）
计划上线日期：YYYY-MM-DD（或：YYYY-MM-DD ~ YYYY-MM-DD）
提测人：
测试对接：慕斯 / 劲风 / 林新
备注：
```

### 7.2 测试环境验收 Checklist

- [ ] 测试 `client_id` / 密钥可用，渠道已开通
- [ ] 回调可达、验签通过、发货幂等
- [ ] 失败单 / 关单 / 超时策略明确
- [ ] 订阅（如有）：首购、续费、取消续订各至少 1 次
- [ ] 商店支付（如有）：沙盒购买与订单状态一致
- [ ] **计划上线日期已确认**，并同步 PM（九姜）

测试验收通过后，方可进入正式环境切换。

---

## 8. Step6：正式环境切换与上线

1. 以 Step5 确认的**上线日期**为准，倒排正式商户、配置与发布窗口。
2. 正式商户就绪 → 九姜开通正式配置 → 切正式网关/密钥/回调。
3. 上线日小流量验证 → 全量。
4. 若上线日期变更，须同步测试、PM、产品，并更新排期。

## 10. CLI / Agent 使用说明

嵌入 CLI 时建议行为：

1. **开场先问清**：业务类型、运行端、市场、渠道 ID、是否已有 `client_id`、**计划上线日期（若已有）**。
2. **按阶段输出**：当前 Checklist + 对接人 + 文档链接 +「下一步唯一动作」。
3. **研发完成后**：提醒交付测试做测试环境验收，并索要/确认上线日期。
4. **实现细节 / 错误码 / FAQ**：跳转官方文档（见 §6 文档路由表），不臆造字段与错误码含义。
5. **安全**：不回显用户真实密钥。

**开场提问模板**

```text
1. 业务类型？(一次性购买 / 订阅 / 签约代扣)
2. 运行端？(Web / Android 内嵌 H5 / iOS 内嵌 H5 / Google Play / App Store)
3. 目标市场？(海外 / 国内)
4. 计划渠道 ID？(1-10，可多选)
5. 是否已有平台 client_id？(有/无；测试或正式)
6. 计划上线日期？(YYYY-MM-DD / 暂未确定)
```
